# Наш чат

Мобильный архив Telegram: 102 979 сообщений с 13 января по 30 октября 2026 года. Оформление для iPhone, поиск по всей истории, фильтр по отправителю, календарь, ответы, реакции, медиа и светлая/тёмная темы. Это самостоятельный архив для чтения.

По умолчанию включена тема по предоставленному образцу: чёрный фон с узором Telegram, полупрозрачные круглые кнопки, тёмные входящие сообщения и переход от фиолетового к синему для исходящих. В настройках она называется «Как на скриншоте». Узор Telegram Web A и его лицензия включены в публикуемую копию; см. `web/ASSET-LICENSES.md`.

## Что загружать

- **GitHub:** этот репозиторий, включая `docs`. Содержимое переписки в `docs/data` зашифровано. В настройках репозитория включите Pages → Source → GitHub Actions; публикацию выполняет `.github/workflows/pages.yml`.
- **Google Drive:** содержимое `media-upload` отдельной папкой, с сохранением вложенных папок `00`, `01` и так далее. Сейчас это 5.9 ГБ в 17 755 файлах. Файлы уже зашифрованы и разбиты на части до 8 МБ. Не упаковывайте в ZIP: сайт читает части по мере просмотра.
- **Только у себя:** `private`, где находятся пароль и промежуточные аудиофайлы. Эта папка исключена из Git.

Исходный экспорт не меняется и не помещается в репозиторий. В копию медиа включены все файлы, на которые ссылается переписка, вместе с миниатюрами. Исходные файлы без ссылок в сообщениях остаются в исходной резервной копии.

## Подключение медиа

В `docs/media-config.json` указывается хранилище. После изменения конфигурации нужно закрыть архив и открыть с паролем заново.

### Google Drive

1. Загрузите папку `media-upload` целиком, вместе с подпапками. Внутри общей папки должны лежать сразу `00`, `01`, … `ff`.
2. Откройте её и скопируйте идентификатор из адреса: `https://drive.google.com/drive/folders/ЭТО_ИДЕНТИФИКАТОР`.
3. Откройте доступ: «Все, у кого есть ссылка» с ролью «Читатель».
4. В Google Cloud Console создайте проект, включите Google Drive API и создайте ключ API. Ключ ограничьте этим же Drive API, а в ограничении по сайтам укажите origin GitHub Pages.
5. Впишите значения:

```json
{"provider":"gdrive","driveFolderId":"ID_ПАПКИ","apiKey":"КЛЮЧ_API","proxyUrl":""}
```

У Диска нет адресуемых путей, поэтому сайт сначала запрашивает список подпапок общей папки, затем список нужной подпапки, и дальше скачивает части по идентификаторам файлов. Списки запрашиваются один раз за сеанс и хранятся только в памяти вкладки.

Не проверяйте загруженную папку массовыми запросами к API: после нескольких сотен подряд Google временно
перестаёт отдавать файлы на скачивание всей сети, с которой шли запросы, и возвращает страницу «your computer or
network may be sending automated queries». Списки папок при этом продолжают работать, а блокировка снимается сама
за десятки минут. Сайт из-за этого показывает «Не удалось загрузить файл из облака». Проверять лучше выборочно,
по нескольким папкам, с паузами.

Ключ API попадает в публичный репозиторий, и это ожидаемо: он даёт только чтение того, что и так открыто по ссылке, а содержимое файлов зашифровано. Ограничение по сайту не даст использовать его с чужого домена.

### Яндекс Диск

```json
{"provider":"yandex","baseUrl":"","yandexPublicUrl":"https://disk.yandex.ru/d/EXAMPLE","proxyUrl":""}
```

Ссылка должна вести на папку с содержимым `media-upload`: непосредственно внутри неё должны быть подпапки `00`, `01` и так далее.

### Обычное HTTPS-хранилище с разрешённым CORS

```json
{"provider":"http","baseUrl":"https://media.example.com/","yandexPublicUrl":"","proxyUrl":""}
```

### Если браузер блокирует скачивание

Общая ссылка ещё не гарантирует воспроизведение внутри сайта: хранилище должно разрешать чтение файлов из Safari на другом домене. На этот случай есть необязательный обработчик — Cloudflare Worker: `scripts/gdrive-media-proxy.mjs` с переменными `DRIVE_FOLDER_ID`, `DRIVE_API_KEY`, `ALLOWED_ORIGIN` или `scripts/yandex-media-proxy.mjs` с `YANDEX_PUBLIC_URL`, `ALLOWED_ORIGIN`. `ALLOWED_ORIGIN` — точный origin GitHub Pages, без пути. Адрес Worker записывается в `proxyUrl`, и тогда сайт обращается только к нему. Обработчик передаёт только шифрованные части и не получает пароль. **Ни один из обработчиков ещё не размещён и не проверен с вашей облачной папкой.**

## Пароль и приватность

Пароль находится локально в `private/ПАРОЛЬ.txt`. Сохраните его в своём менеджере паролей и передайте ей отдельно. Изменение текста этого файла **не меняет шифрование**. Для смены пароля потребуется полностью пересобрать архив и медиа с новым ключом; сначала сохраните исходный экспорт.

Данные шифруются AES-256-GCM с отдельным случайным nonce для каждого файла/части. Ключ выводится из пароля через PBKDF2-SHA256 (600 000 итераций, случайная соль). Ключ и расшифрованные данные не записываются в постоянное браузерное хранилище. На устройстве сохраняются только оформление, имя контакта и номер позиции чтения.

Посетители всё равно видят оболочку сайта и могут скачать зашифрованные файлы. Пароль нужен для их расшифровки. После ввода пароля доверять нужно также коду, опубликованному в этом репозитории. Не публикуйте папку `private` и не отправляйте пароль вместе со ссылкой в публичном месте.

## Запуск и проверка

Требуются Python 3.11+, пакеты из `scripts/requirements.txt`, FFmpeg для голосовых. Зависимостей Node для сайта нет.

```powershell
python -m pip install -r scripts/requirements.txt
python scripts/build_archive.py "C:/path/to/telegram-export" --media
python scripts/verify_archive.py "C:/path/to/telegram-export"
python scripts/check_publish.py
python -m http.server 8765 --bind 127.0.0.1 --directory docs
```

Откройте `http://127.0.0.1:8765`. Открытие `index.html` через `file://` не поддерживается. GitHub Pages работает по HTTPS; на iPhone нужен Safari 16.4 или новее. Для добавления значка в Safari: «Поделиться» → «На экран Домой».

Для локальной проверки **с медиа**, без загрузки в облако: `python scripts/preview.py`, затем `http://127.0.0.1:8766`. Этот сервер доступен только на компьютере и подставляет локальное хранилище временно, не меняя настройки опубликованного сайта.

В `web` хранится исходный интерфейс, в `docs` — публикуемая копия. Для обновления только интерфейса скопируйте изменённые файлы из `web` в `docs`. Для изменения импортируемой истории запустите сборщик. Повторная сборка переиспользует локальный пароль и уже подготовленные медиа; после изменения самого экспорта желательно создать отдельную новую сборку, чтобы не смешивать старые файлы.

Видео и голосовые воспроизводятся с запросами диапазонов через Service Worker. Это позволяет читать отдельные шифрованные части вместо загрузки большого видео целиком в память iPhone. При выгрузке Service Worker браузером может потребоваться закрыть и заново открыть файл.

## Ограничения

- Нужен интернет; это не полная офлайн-копия на iPhone.
- Есть только данные, сохранённые в экспорте. Удалённых до экспорта сообщений в нём нет.
- В экспорте есть 79 сообщений с недоступными/истёкшими вложениями. Их заглушки сохранены; отсутствующие файлы восстановить из экспорта нельзя.
- У части служебных событий экспорт не содержит времени; они показаны на месте в истории без выдуманной отметки времени.
- TGS-стикеры открываются в просмотрщике через локальную копию lottie-web; миниатюра в ленте может быть только эмодзи.
- Форматы видео зависят от поддержки Safari. Реальное воспроизведение на iPhone и доступ из облака нужно проверить после подключения хранилища.
